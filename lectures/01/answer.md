- 課題：`app/ask.py` を改修し、会話履歴を保ったまま続けて質問できるようにする
- やったこと：
  1. `app/ask.py` に `--chat` オプションを追加し、同じチャットセッションに続けて質問を送る対話モードを実装した。
  2. 対話モード・通常の1問だけの実行のどちらでも、回答の後に入力・出力トークン数とモデルバージョンを表示するようにした。

- 結果：

  ■ コードの変更

  - `--chat` は `parser.add_argument("--chat", ...)` で定義し、`if args.chat:` で対話モードを選ぶ。
    起動は `uv run python -m app.ask --chat`。実行中は同じチャットセッションに質問を送るため、会話履歴が保たれる。
    終了は `/exit`、`/quit`、または `Ctrl-D`。
  - `--chat` は、質問を省略したときに使われる `default=DEFAULT_QUESTION` とは別の仕組みである。
    `--chat` を指定した場合は既定の質問を使わず、入力待ちになる。
  - `tests/test_ask.py` に追加したテストは次の2点を確認するもの。
    - 同じセッションへ複数の質問が送られること
    - 回答の後にトークン数が表示されること
    これは自動テスト用で、アプリの実行には必要ない。今後のテストで使う可能性があるため残している。
  - 今日の作業では、アプリとテストを実行していない。したがって、コード変更後の実行結果は未確認。

  ■ 会話で確認したこと

  - 「今日の千葉市の天気」を尋ねたとき、`app.ask` は質問を Gemini に送るだけで、検索や天気取得をしない。
    そのため、最新の天気を確認した回答にはならない。
  - 会話モードでは同じ会話の過去のやりとりも後続の質問とともに扱われるので、入力トークン数は質問文だけの量とは限らない。
  - 最新情報を加える案として Google Search 連携、SerpApi、Open-Meteo を話題にした。

    これは自分が実行時に確認した値で、このレポート作成時に再実行して確認したものではない。

- 取り組んだレベル：発展

- 方法：
  - 質問A「LoRAとは何ですか？」と、質問B「LoRAとは何ですか？仕組みや用途も含めて、初めて学ぶ人向けにもっと詳しく解説してください。」を用意した。
  - 各質問を3種類のモデルでそれぞれ3回、同じ条件で実行した。
  - 応答時間は、API呼び出し直前から応答を受け取るまでを `time.perf_counter()` で計測した。APIキー取得やクライアント作成にかかる時間は含めていない。
  - 入力・出力トークン数と、指定モデル名に加えて実際の `model_version` も記録した。
  - 応答が返らなかった試行もあったため、下表には計測値を取得できた試行を掲載する。質問Bの `gemini-3.5-flash` は混雑を示すメッセージが出て再試行し、成功した3回分を記録した。

- 質問A：短い質問「LoRAとは何ですか？」（入力トークン数はいずれも7）

  | 指定モデル | 実際のモデル | 試行1（秒 / 出力トークン） | 試行2（秒 / 出力トークン） | 試行3（秒 / 出力トークン） | 平均応答時間 | 平均出力トークン数 |
  |---|---|---:|---:|---:|---:|---:|
  | `gemini-3.5-flash` | `gemini-3.6-flash` | 12.17 / 846 | 17.84 / 779 | 9.52 / 594 | 13.18秒 | 740 |
  | `gemini-3.5-flash-lite` | `gemini-3.5-flash-lite` | 9.09 / 593 | 7.45 / 546 | 8.86 / 597 | 8.47秒 | 579 |
  | `gemini-3.1-flash-lite` | `gemini-3.1-flash-lite` | 4.54 / 724 | 3.61 / 707 | 74.06 / 717 | 27.40秒 | 716 |

- 質問B：詳しい説明を求める質問（入力トークン数はいずれも23）

  | 指定モデル | 実際のモデル | 試行1（秒 / 出力トークン） | 試行2（秒 / 出力トークン） | 試行3（秒 / 出力トークン） | 平均応答時間 | 平均出力トークン数 |
  |---|---|---:|---:|---:|---:|---:|
  | `gemini-3.5-flash` | `gemini-3.6-flash` | 16.63 / 1,445 | 17.50 / 1,150 | 16.00 / 1,197 | 16.71秒 | 1,264 |
  | `gemini-3.5-flash-lite` | `gemini-3.5-flash-lite` | 8.99 / 1,071 | 26.86 / 1,118 | 9.40 / 1,001 | 15.08秒 | 1,063 |
  | `gemini-3.1-flash-lite` | `gemini-3.1-flash-lite` | 5.55 / 1,040 | 5.44 / 1,079 | 5.42 / 1,016 | 5.47秒 | 1,045 |

- 気づき・疑問：
  - 【事実】質問Aの入力トークン数は7、質問Bは23だった。質問Bの平均出力トークン数は、3モデルすべてで質問Aより多かった。
  - 【考察】詳しい説明を求める質問では、今回の測定でより長い回答が生成された。ただし、各条件3回の結果なので、質問の長さだけが出力トークン数の差を生んだとは断定できない。
  - 【事実】応答時間には試行ごとのばらつきがあった。例えば `gemini-3.1-flash-lite` は質問Aで74.06秒かかった一方、質問Bの3回は約5.4秒だった。`gemini-3.5-flash-lite` も質問Bの2回目だけ26.86秒だった。
  - 【考察】応答時間は出力トークン数だけでは説明できず、通信状況やサービス側の混雑なども影響した可能性がある。今回の平均値は測定した範囲の要約であり、常に同じ速度になることを示すものではない。
  - 【事実】`gemini-3.5-flash` を指定したとき、応答の `model_version` は `gemini-3.6-flash` と表示された。
  - 【事実】質問Bの測定中に「モデルが混み合っています（503）。少し待ってから再実行してください。」というエラーが出た。時間を空けて再実行すると回答を得られた。
  - 【考察】今回確認した503はモデル側の混雑を示すエラーで、レート制限としてよく見られる429とは区別される。今回の測定では429は確認していないため、レート制限に達したとは言えない。一方、503による一時的な使いにくさは観測できた。
  - 【疑問】応答時間のばらつきや503の発生が、時間帯やサービスの混雑とどの程度関係するかは未確認。さらに調べるなら、実行時刻、エラーコード、AI Studioの利用状況も記録して比較したい。
